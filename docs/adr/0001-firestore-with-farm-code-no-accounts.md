# Firestore with a Farm Code, no accounts

Progress used to live in each browser's `localStorage`, and moving it between devices meant copying and pasting a backup code. Now it syncs through Firebase Firestore using invisible anonymous sign-in. Each Farm's Progress lives under its Farm Code, which is carried in the address fragment (`/fish#<farm-code>`) so it never reaches the host. Whoever holds the code can read and change that Progress. Unlike mk-tracker, you pick the Farm Code yourself (e.g. `mcnew-farm`) instead of the app generating an unguessable one. So someone who guesses it could edit that Farm, which we accept for a game checklist. Starting a Farm saves it straight away and refuses a code that's already in use. Opening a Farm refuses a code that doesn't exist. We skip real accounts because the only user is one player on a few devices, and a login is friction on a phone. One code is one Farm (one save), not one person, because that's how the game keeps progress. The site is static files on Cloudflare Workers and installs as a Home Screen web app that works offline.

This copies the approach proven in mk-tracker (its ADRs 0002, 0004 and 0006), including its lessons: the Farm Code must stay in the visible address, because a Home Screen app starts from that address and doesn't share Safari's storage, and the service worker must update itself. The Copy/Restore backup codes are dropped, because sync replaces them.
